# API Reference — `Beeleex.Api`

`Beeleex.Api` interfaces with the Beelee GraphQL server to manage Business
Units, companies, invoices and credit notes. API calls:

- POST to `beelee_endpoint` (default `https://beelee.geeks.solutions/v0-1/api`)
  via `ExGeeks.Helpers.endpoint_post_callback/3`.
- Send `content-type` and `bu-id` (`business_unit_id`) headers. Server-to-server
  calls send `secure-key` (`business_unit_secure_key`); token-authenticated
  calls send `bu-authorization: Bearer <token>`.
- Atomize/underscore response keys and return `{:ok, result}` or, on GraphQL
  errors, log and return `{:error, message}`.

## Functions

### `get_business_unit(id)`
`integer() | String.t() :: {:ok, Beeleex.BusinessUnit.t()} | {:error, String.t()}`

Loads a Business Unit through Beelee's `getBusinessUnit(id: Int!)` query. This
is a server-to-server call and sends configured `secure-key` and `bu-id` headers.
Host applications can use this response to build the complete input required by
`edit_business_unit/2`.

### `edit_business_unit(id, business_unit_input)`
`(integer() | String.t(), map()) :: {:ok, Beeleex.BusinessUnit.t()} | {:error, String.t()}`

Updates a Business Unit through Beelee's `editBusinessUnit` mutation. The input
map must use GraphQL camelCase keys: `cycle`, `name`, `startCycleDate`,
`tokenValidationUrl`, `verifyCardAttachment`, and `webhookUrl`. This is a
server-to-server call and sends configured `secure-key` and `bu-id` headers.
Because Beelee's `BusinessUnitInput` has required fields, callers must pass a
complete input map.

### `run_next_scheduled_business_unit_cycle(id)`
`integer() | String.t() :: {:ok, Beeleex.BusinessUnit.t()} | {:error, String.t()}`

Runs Beelee's `runNextScheduledBusinessUnitCycle(id: Int!)` mutation for the
given Business Unit. This is a server-to-server call and sends configured
`secure-key` and `bu-id` headers.

### `update_invoices(invoices)`
`list(Beeleex.InvoiceUpdate.t()) :: {:ok, String.t()} | {:error, String.t()}`

Accepts pricing and issues invoices generated by Beelee for a billing cycle.
Returns the existing confirmation message or the API's first validation error.
Omitting `currency` keeps a cycle draft's currency, selected from the BU
default when the draft was created. If the invoice currency differs from the
billing centre reporting currency, supply an exact decimal string in
`exchangeRate` (reporting currency units per invoice currency unit).
`taxPointDate` is optional. An identical retry leaves the issued invoice,
reference and payment job unchanged. The library does not retry automatically.

### `get_company_by_customer_project(customer_project)`
`String.t() :: {:ok, Beeleex.Company.t()} | {:error, String.t()}`

Returns the company linked to one of your `customer_project` IDs. The returned
company is enriched via `Beeleex.Company.compute_bu_cycle/1`.

### `generate_onetime_invoice(onetime_payment)`
`Beeleex.OnetimePayment.t() :: {:ok, Beeleex.Invoice.t()} | {:error, String.t()}`

Issues a one-time invoice and starts collection. Returns the invoice with
its tags. Omitted `currency` uses the BU default. `exchangeRate` and
`taxPointDate` follow the same rules as `update_invoices/1`.

### `get_invoice(token, invoice_id)`
`(String.t(), integer() | String.t()) :: {:ok, Beeleex.Invoice.t()} | {:error, String.t()}`

Fetches a single invoice by Beelee ID using the caller's token. The invoice's
`tags` field contains the original tag strings, such as
`checkout_operation:<uuid>`. This applies to one-time, cycle-based, and batched
invoices. An empty list stays `[]`; omitted or null tags are `nil`.

### `get_invoices(token, opts \\ [])`
`(String.t(), keyword()) :: {:ok, %{invoices: [Beeleex.Invoice.t()], total: integer(), count: integer()}} | {:error, String.t()}`

Lists invoices using the caller's token. Accepts `:filter`, `:size`, and `:skip`.
Each invoice includes tags with the same behavior as `get_invoice/2`.

### `get_current_cycle_invoices(company_id, project_id, tag)`
`(String.t(), String.t(), String.t()) :: {:ok, list(Beeleex.Invoice.t())} | {:error, String.t()}`

Loads up to 50 invoices for a company filtered by project ID and tag within the
current cycle. The returned invoices retain all of their tags, not just the
filter tag. Returns `{:error, "no_match"}` when count is 0.

### `generate_credit_note(amount, originating_invoice_id, reason, tags \\ [])`
`(integer(), integer(), String.t(), list(String.t()) | nil) :: {:ok, Beeleex.CreditNote.t()} | {:error, String.t()}`

Creates a credit note against an originating invoice. `amount` must use the same
decimal places as the originating invoice. `tags` is optional.

### `get_credit_notes_for_invoices(company_id, invoices)`
`(String.t(), list(Invoice.t())) :: ...`

Fetches the credit notes associated with the provided invoices for a company.

### `request_credit_in_cycle(company_id, max_amount, search_tag, reason, tags)`
`(String.t(), integer(), String.t(), String.t(), list(String.t())) :: ...`

Requests a credit (up to `max_amount`) within the current cycle, scoped by
`search_tag`, with a `reason` and optional `tags`. Useful when a project plan
changes mid-cycle.

The credit-note APIs include tags on the nested `originating_invoice` map
when Beelee returns them. These are separate from the credit note's own tags.

> For exact GraphQL fields and the freshest signatures, read the `@doc`/`@spec`
> annotations in `lib/beeleex/api.ex`.
